# CowdeISreal

**CowdeISreal** — самостоятельное приложение для сообществ: серверы-сообщества, текстовые/голосовые/объявительные каналы, роли и права, приглашения, сообщения в реальном времени, голос/камера/демонстрация экрана, профили с приватностью, метки, ранги и модульные боты-команды.

**Для участников базовые функции бесплатны** и не блокируются подпиской. Расходы на инфраструктуру несёт владелец инстанса — см. [«Расходы и лимиты»](#расходы-и-лимиты).

> RootApp и DiggersBtwModes: исходные материалы в доступной среде **не найдены**, функции оттуда не переносились. Подробности и точки интеграции: [`docs/PRODUCT_AUDIT.md`](docs/PRODUCT_AUDIT.md), [`docs/ROOTAPP_FEATURE_MAP.md`](docs/ROOTAPP_FEATURE_MAP.md), [`docs/DIGGERS_BOTS_TODO.md`](docs/DIGGERS_BOTS_TODO.md).

## Стек
- **Фронтенд:** Vite, React 19, TypeScript, react-router. Собственная плоская дизайн-система «Графит»: без градиентов и свечения, тёмная основа, зелёный акцент; другие цвета только функциональные (голосовые комнаты — голубые, объявления — янтарные, ошибки — красные). 13 тем, светлая в том числе. Собственные SVG-иконки и логотип-шестигранник.
- **Интерфейс** намеренно не повторяет Discord: сообщества — вкладки в верхней панели, комнаты — список с цветом по типу, лента — пузыри (свои справа), ответы ботов — заметки с синей полосой, люди — выезжающая панель, звонок — плавающий док, голосовая комната — круглые аватары.
- **Бэкенд:** Supabase — Postgres (RLS + RPC), Auth, Storage, Realtime. Вся логика прав — в одной миграции `supabase/migrations/20261101000000_init.sql`.
- **Медиа:** WebRTC. Supabase Realtime — только сигнализация (SDP/ICE) через приватные broadcast-топики, не медиасервер.

## Быстрый старт

```bash
npm install
```

1. Создайте проект на supabase.com.
2. Примените **обе** миграции по порядку: Supabase → SQL Editor → вставить `supabase/migrations/20261101000000_init.sql` → Run, затем `supabase/migrations/20261102000000_social.sql` → Run, затем `supabase/migrations/20261103000000_fix_search_readonly.sql` → Run (повторный запуск безопасен; вторая включает расширения `pg_trgm` и `fuzzystrmatch` для поиска с опечатками) — или через CLI:

```bash
supabase link --project-ref <ref>
```

```bash
supabase db push
```

3. Скопируйте `.env.example` в `.env`, укажите `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` (Project Settings → API). **`service_role` в `.env` фронтенда не кладите никогда.**
4. Authentication → URL Configuration: Site URL = адрес сайта.
5. **Регистрация по коду из письма:**
   - Authentication → Providers → Email: включите **Confirm email**.
   - Authentication → Email Templates → **Confirm signup**: вставьте `supabase/templates/confirmation.html` (в письме будет 6-значный код `{{ .Token }}`, а не ссылка).
   - Там же **Reset Password**: вставьте `supabase/templates/recovery.html` — сброс пароля тоже по коду.
   - Для реальной рассылки подключите свой SMTP (Authentication → Emails → SMTP): встроенная почта Supabase предназначена для тестов и сильно ограничена по количеству писем.
   - При локальном `supabase start` шаблоны и длина кода уже заданы в `supabase/config.toml`; письма смотрите в Inbucket/Mailpit (адрес покажет CLI).
6. Realtime: приватные топики (`voice:`, `typing:`, `community:`) авторизуются политиками на `realtime.messages`, которые создаёт миграция. Если в настройках Realtime есть режим «только приватные каналы» — включите его.

```bash
npm run dev
```

Без шага 3 приложение честно показывает экран настройки, а не нерабочий интерфейс.

**Деплой:** `npm run build` → статическая папка `dist/` на любой хостинг статики (Cloudflare Pages, Netlify, Vercel, GitHub Pages). Нужен fallback всех путей на `index.html` (SPA). Камера/микрофон/экран работают только по HTTPS (или на localhost).

## Друзья, личные сообщения, знакомства
- **Поиск людей** по @handle или имени с подсказками при опечатке: «Возможно, вы имели в виду…». Похожесть строк (`pg_trgm`) плюс расстояние Левенштейна (`fuzzystrmatch`) для коротких ников (`bbo` → `@bob`).
- **Заявки, а не мгновенное добавление.** Дружба появляется только после «Принять». Если оба отправили заявки друг другу, они объединяются сразу. После отказа повторная заявка возможна через 7 дней.
- **Приватность** (Настройки → Друзья и приватность): кто находит меня (все / только по точному handle / никто), кто шлёт заявки (все / с общими друзьями или сообществами / никто), личные сообщения (от друзей / ни от кого).
- **Блокировка**: заблокированный не найдёт вас в поиске, не откроет профиль, не пришлёт заявку и не напишет. Факт блокировки не раскрывается: для него вы будто не существуете.
- **Личные сообщения** только между друзьями: правка, удаление, непрочитанное, realtime. После удаления из друзей история остаётся, отправка закрывается.
- **Знакомства** — поиск друзей, не свиданий. Ленту видят только те, кто сам включил анкету; геолокации нет. Свайп вправо = заявка (дружба после принятия). Лимиты: 50 лайков и 300 свайпов в сутки, 30 заявок в час. Кнопка «Пожаловаться» в карточке.
- **Жалобы** пишутся в таблицу `user_reports`. Участникам она недоступна (RLS); владелец инстанса читает её в Supabase → Table Editor. Модерацию жалоб нужно организовать самому — без этого кнопка бесполезна.

## Кастомизация: 176 настроек
Реестр `src/lib/customize.ts`: 17 разделов, **176 настроек** (66 переключают стили через `data-*`, 23 управляют CSS-переменными, 87 меняют поведение в коде) и 178 вариантов в выпадающих списках. Среди них 12 тем, 8 стилей пузырей, узоры фона, шрифты, раскладка (комнаты слева или справа, панель снизу), рация (push-to-talk), тихие часы, фильтр и подсветка слов, черновики, формат времени, режим стримера и другое. Экран настроек строится из реестра: поиск, сброс раздела и всего. Настройки синхронизируются через аккаунт.

Отдельно — **оформление профиля, которое видят другие**: цвет и узор баннера, рамка аватара, шрифт имени, эмодзи, местоимения.

Тест `src/lib/customize.test.ts` (242 проверки) гарантирует, что пустышек нет: для каждого значения стилевой настройки в CSS есть правило, каждая CSS-переменная используется, каждую логическую настройку читает код.

## Безопасность и права

- **Чтение** — через RLS: участник видит только свои сообщества, только каналы с правом просмотра (с учётом переопределений), сообщения/реакции/вложения — только в видимых каналах.
- **Запись** — только через `security definer`-функции; прямые `INSERT/UPDATE/DELETE` из браузера отозваны (кроме избранного и своих приватных полей профиля). `user_id` берётся из `auth.uid()`, `community_id` — из канала/сообщения, а не от клиента.
- **Права** — битовая маска (`src/lib/permissions.ts` ⇄ SQL): просмотр, отправка, вложения, реакции, управление сообщениями, приглашения, каналы, роли, участники, метки, модерация, настройки сообщества, команды, голос, видео, администратор. Владелец — все права.
- **Иерархия** — действовать (кик, бан, таймаут, XP) можно только на тех, чья верхняя роль строго ниже; создавать/менять/выдавать — только роли ниже своей и только с правами, которые есть у тебя самого. Владельца нельзя кикнуть/забанить/заглушить. Передача владения — с подтверждением названием.
- **Антиспам** — лимиты частоты в БД (сообщения 5/5 с и 60/мин, команды 10/мин, реакции, приглашения, вступления, правки, смена handle), медленный режим каналов, лимиты длины (4000 символов), до 5 вложений, лимиты сущностей (каналы, роли, метки, приглашения, закрепы).
- **Аудит** — все административные действия пишутся в `audit_log` (виден с правом «Модерация»).
- **Storage** — `attachments` приватный (10 МБ, белый список MIME), путь `<community>/<channel>/<user>/<файл>`, загрузка только автором с правом вложений, чтение — по праву просмотра канала, выдача через подписанные URL на 1 час; размер и тип для сообщения берутся из `storage.objects`, а не от клиента. `public-media` — публичные аватары/иконки (2 МБ, только изображения).

## Голос, камера, экран

- **Сейчас:** mesh-WebRTC (perfect negotiation). Каждый соединён с каждым, исходящий трафик участника растёт линейно. Лимит комнаты проверяется в БД (`voice_mesh_limit`, 2–8, по умолчанию 6). **Mesh не масштабируется на большие звонки** — это сознательное ограничение.
- **Приватность:** вход в комнату не включает микрофон; микрофон, камера и экран включаются только по нажатию; при выключении треки останавливаются (индикатор браузера гаснет). Ничего не записывается.
- **Ошибки:** отдельные понятные сообщения для запрета доступа, отсутствия устройства, занятого устройства, не-HTTPS, неподдерживаемой демонстрации экрана (iOS/большинство Android), недоступного Realtime, отсутствия TURN.
- **STUN/TURN:** `VITE_STUN_SERVERS` — только STUN. Для пользователей за строгим NAT нужен **TURN**, он ретранслирует трафик и **стоит денег** у провайдера (или ресурсов вашего сервера при self-hosted coturn). Учётки TURN выдаёт Edge Function `turn-credentials` (HMAC, срок 1 час); секрет живёт в Supabase Secrets:

```bash
supabase secrets set TURN_SECRET=... TURN_URLS='["turn:turn.example.com:3478?transport=udp","turns:turn.example.com:5349"]'
```

```bash
supabase functions deploy turn-credentials
```

  Затем `VITE_TURN_ENABLED=true`.
- **SFU (путь масштабирования):** интерфейс `CallEngine` (`src/lib/rtc/provider.ts`) и Edge Function `sfu-token` (выдаёт JWT доступа к комнате LiveKit после проверки прав в БД; секреты — только на сервере) готовы. **Клиентский адаптер SFU не реализован**: при `VITE_CALL_PROVIDER=sfu` приложение честно сообщает об этом. План: добавить `livekit-client`, реализовать `SfuCall implements CallEngine`, снять лимит `voice_mesh_limit` для SFU-комнат.

## Ранги
Серверная механика: XP только за содержательные сообщения (минимальная длина), пауза между начислениями, дневной лимит, повтор того же текста не награждается, команды не награждаются, одна выдача на сообщение (уникальный индекс). Владелец настраивает или отключает в «Настройки → Ранги». Ручная корректировка — только модератором, с причиной, в журнал. Ранги не дают прав и не связаны с оплатой. Уровень L требует `25·L·(L+1)` XP.

## Боты и команды
Реестр `src/lib/commands.ts` (справка, автодополнение по Tab), исполнение — только на сервере в `public._run_command`: фиксированные ветки SQL, без eval/shell/сети. Проверки: модуль включён в сообществе, право «Команды ботов», лимит частоты, журнал `bot_command_log`. Сейчас есть только **модуль-пример** (`/help /rank /top /roll /coin`), помеченный «пример» и отключаемый. Как добавить реальные модули — `docs/DIGGERS_BOTS_TODO.md`.

## Расходы и лимиты

Цифры квот здесь намеренно не приводятся: тарифы Supabase и TURN-провайдеров меняются. Актуальные значения — на страницах цен провайдеров и в **Supabase → Project → Usage**.

| Ресурс | Что расходует | Как ограничено в приложении | Мониторинг |
|---|---|---|---|
| БД | сообщения, аудит, XP-события | лимиты длины и частоты, лимиты сущностей | Usage → Database size |
| Storage | вложения, аватары, иконки | 10 МБ / 2 МБ, белый список типов, до 5 файлов | Usage → Storage, Egress |
| Исходящий трафик | скачивание вложений | подписанные URL на 1 час | Usage → Egress |
| Realtime | соединения, сообщения, сигнализация | 20 событий/с на клиента, сигнализация только в комнате | Usage → Realtime |
| Edge Functions | выдача TURN/SFU-токенов | только для вошедших, только при включении | Usage → Functions |
| TURN | ретрансляция медиа | выключен по умолчанию | у TURN-провайдера |

**Переход на платный тариф** делает владелец инстанса в Supabase → Billing; участников это не касается. Включите spend cap / бюджетные оповещения, чтобы избежать неожиданных счетов. Платные внешние API приложение само не подключает.

1. Клиентский SFU-адаптер (LiveKit) и снятие mesh-лимита для SFU-комнат.
