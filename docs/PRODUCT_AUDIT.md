## Что найдено полезного (не RootApp, но влияет на решения)
- `codwe-ai/supabase/schema.sql`, `ranks.sql`: владелец уже использует Supabase, пишет **идемпотентные** SQL-файлы с русскими комментариями для запуска в SQL Editor, переносит все проверки в `SECURITY DEFINER`-функции и RLS, применяет иерархию «действовать можно только на тех, кто строго ниже». Эти конвенции перенесены в `supabase/migrations/…_init.sql`.
- Сайты владельца — на чистом HTML/JS; для приложения такого объёма выбран Vite + React + TypeScript (меньше ручной работы с состоянием, статическая сборка, тот же бесплатный хостинг статики).

## Текущий стек (выбран)
- Фронтенд: Vite, React 19, TypeScript, react-router. Без UI-библиотек: собственная дизайн-система на CSS-переменных.
- Бэкенд: Supabase — Postgres (RLS + RPC), Auth, Storage, Realtime (postgres_changes для сообщений, приватный broadcast для сигнализации WebRTC и индикатора набора).
- Медиа: WebRTC mesh (до 6 участников, лимит проверяется в БД), интерфейс SFU-провайдера, Edge Functions для краткоживущих TURN-учёток и SFU-токенов.

## Недостающие сведения (нужны от владельца)
1. Описание RootApp: что это за продукт, ключевые сценарии, ссылки на код/макеты.
2. Описание ботов DiggersBtwModes: список ботов, команды, права, данные.
3. Целевой масштаб (сколько участников в звонке/сообществе) — определяет, нужен ли SFU сразу.
4. Supabase-проект для инстанса (URL + anon key), TURN-провайдер (если нужен).

## Предположения (помечены, легко меняются)
- «Ранги» = уровни опыта внутри сообщества, а не роли доступа (в codwe-ai ранги = роли; здесь роли и ранги разделены, потому что ранги не должны давать права автоматически).
- ЛС и групповые чаты — следующий этап (см. README → «Дорожная карта»).
